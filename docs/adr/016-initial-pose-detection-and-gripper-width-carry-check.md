# ADR 016: 视觉只做初始位姿检测，搬运期用夹爪开度；先测容差与误差再落地

- 状态：已决定（接口细节与阈值在对应阶段冻结，见“尚未决定”）
- 日期：2026-10-05
- 范围：视觉在任务中的职责、搬运期完整性的信号来源、验证方法
- 取代：[ADR 015](015-rollback-stage6-perception-side-transport-diagnostics.md) 的第 2~5 条（附着期持续视觉、perception 内的 TCP 推算与同帧比较）和第 7 条的排期。ADR 015 保持历史快照，其第 1、6、8 条仍然有效
- 关联：[ADR 010](010-grasp-conditioned-object-state.md)、[ADR 011](011-vision-object-pose-contract-tightening.md)、[ADR 012](012-prelift-attachment-confirmation.md)、[ADR 013](013-partial-cube-geometry-admission.md)；[Week 4.1](../../Job_guides/my_study/week4.1.md)

## 背景

ADR 015 在回退 Stage 6 时保留了“附着期视觉持续运行，并在 perception 内用 TCP 推算做同帧比较”。Week 4.1 Stage 2 实现了持续视觉的第一步，并用真实运行加真值标注的离线分析检验了这个前提（2026-10-05，仿真，下列数字均为单次采集，样本小）：

- 附着期视觉大部分被拒：4 个 episode 共 45 帧，`MEASURED` 约 22%；用户自己的话题转储 30 帧里 4 帧（13%）。
- 被拒不是因为看不见盒子。真值标注显示附着期盒体深度像素平均约 164 个，机器人遮罩只擦掉约 6%，红色像素几乎没有被擦。拒绝来自用包围盒边长判断“像不像 40 mm 立方体”：顶面加前面的 L 形可见面，其 PCA 三个边长的理想值是 56.6 / 40.0 / 28.3 mm，正好落在上限 55 mm 和下限 25 mm 的边上。
- 控制是离线 IK：盒子一旦被夹住，世界位姿由 TCP 决定，搬运期没有任何控制环路消费视觉位姿。即使检测到偏差，现在也没有恢复动作。
- 夹爪开度是 bridge 发布的本体状态（`BridgeObservation.joint_state` 里两个手指的位置），不经 executor 转发。搬运时 37.7~40.1 mm（标准差 0.59 mm），张开 80 mm，空夹合拢后 0 mm。
- 初始位姿是视觉真正必需的输入。深度图投影到桌面后取最小面积矩形，在 10 个 yaw 上无噪声误差为 0.00°、中心误差约 1 mm；加 σ=1~4 mm 的高斯深度噪声，yaw 误差 p90≤2.3°、最大 4.5°。而 oracle 抓放在盒子相对夹爪偏 0~30° 时成功，45° 失败。
- 现有估计器不估 yaw：旋转取单位阵，位置用世界轴对齐包围盒。默认 yaw=0 所以一直没暴露。

## 决策

1. **视觉只在物体不被夹持时工作。** 两个用途：(a) 场景静止、机械臂在 HOME 时，一次性检测 box 与 bin 的初始位姿（box 的 x、y、yaw，bin 的 x、y、yaw，高度由桌面与已知几何给出）；(b) 释放后检测 box，供 VERIFY 判断是否在 bin 内。估计器在 ATTACHED 时暂停处理，这保持 Stage 5 基线的行为。
2. **executor 对检测结果做一次性锁存。** reset 后等待多帧一致的 box 与 bin，锁存，任务目标取自锁存值。重试时重新检测并重新锁存，因为失败的抓取可能推动了盒子。
3. **搬运期完整性来自夹爪开度。** 开度由 bridge 发布；检查规则是搬运阶段的开度窗口。窗口宽度与违反窗口时的响应（只告警，还是触发重试）在对应阶段按数据决定，不预先写死。
4. **取消 ADR 015 的搬运期视觉。** `predicted_pose` / `T_tcp_box`、perception 内的同帧比较与 WARNING、离桌顶面准入放宽、附着期持续视觉，都不做。那次实验里写的代码（去掉 `kAttached` 早退、`ReleaseGuard`）因此失去用途，已还原或删除，只保留了删除冗余的 `vision_cache_` 这一项。
5. **先测再落地，且在测量前写死评测协议。** 先测“要多准”（抓取与放置对位姿误差的容差），再测“能多准”（检测的离线误差表）；接受规则在看到误差表之前固定为：p95 误差 ≤ 容差的 1/4，最大误差 ≤ 容差的 1/2，漏检按失败计。布局数据集分开发集与留出集，留出集到最终验收才用。
6. **ADR 015 的第 1、6、8 条不变：** 场景位姿只在 bridge；Stage 6 的运输状态机不进入代码；bin 位姿来自视觉，不由配置过滤。

## 尚未决定

在对应阶段开始前确认；任一选择若与上文方向冲突，新增 ADR，不改本文。

- 是否用颜色。深度加高度带可能已经够用，由误差表决定；真实传感器上的颜色需要标定与光照处理，决定时要算上这一项。
- 估计器目前要求 RGB 与深度按时间戳配对才处理；实测 RGB 在传输上丢帧很多（只开 bridge 时 RGB 收到约 1/3，深度全收到），原因未明。检测若不用颜色，是否去掉这个依赖。
- 桌面在仿真里是 0.22 m 的已知先验；真实场景需要平面拟合，何时加。
- bin 结果的消息形态；锁存结果的发布形态。
- 开度窗口违反时的响应；bridge 的附着确认何时不再读 box 真值（ADR 012 的遗留）。
- bin 壁高是否需要从 12 mm 加到 25 mm，由检测误差表与夹爪净间隙共同决定。

## 权衡与后果

- **得到：** 视觉职责窄而明确，可以用一张误差表验收；去掉了一整套需要在遮挡下可靠工作的搬运期视觉；检测对象是静止的，误拒几乎没有代价，可以只在“好”的时刻接受。
- **失去：** 看不到“盒子在夹爪里发生位移但开度不变”的情形；搬运期的视觉不再提供独立于开度的证据。离线 IK 没有闭环用它，最终由 VERIFY 兜底，所以这个损失在当前控制方案下可以接受，但若以后引入闭环或学习式策略，需要重新评估。
- **依赖的假设：** HOME 位姿下机械臂不遮挡工作区；桌面高度已知；盒子平放（roll、pitch 为 0）；开度信号在真实夹爪上也足够干净。前两个由 Stage 3 的误差表检验，后两个目前只是假设。真实夹爪的开度有噪声和偏置，打滑未掉落时也看不出来。
- **仿真的局限：** 误差表在仿真里测得，深度噪声按独立高斯模拟，真实传感器在边缘有飞点和量化；因此精度门槛要留余量，且这些数字不能当作真机精度。
