# ADR 009：用机器人几何与时序证据完成视觉抓放

## Status

已决定，Week 4 Stage 4 已实现并验证，Stage 5~6 待实施（2026-09-30）。本文将已验证的 Stage 4 与后续目标分开记录。

## Context

Stage 2 的视觉节点按单帧 RGB-D 去桌面、取最大点簇、拟合盒体 OBB。Stage 3 让任务层消费该 pose，但每个新视觉样本只要被拒绝，就立即结束 episode。已实测初始 `accepted=true` 的位姿进入 `PREGRASP`；机械臂靠近后与盒体形成混合点簇，估计器报 `MODEL_EXTENT_MISMATCH`，任务以 `VISION_REJECTED` 结束。当前只证明了停止语义，没有完成 vision 模式抓放。

单次初始位姿可以给静止盒体生成抓取目标，但不能观测其抬升、滑落或放置。现有 `makeObservationSnapshot()` 把同一物体 pose 同时用于 waypoint、盒体高度、盒体到 TCP 距离和最终落点验收。只缓存首帧并让后续帧继续使用它，会把过期规划坐标误作当前物理证据。`BridgeObservation` 还含仿真物体真值和接触位；它们不得在 vision 模式下隐式决定在线成功。

## Decision

视觉能力继续归属独立的 `mujoco_perception` 包，`mujoco_bridge` 保持相机和机器人状态源。感知输入使用 RGB-D、CameraInfo、同帧生命周期键、关节/夹爪状态、现有 TF 和经实测核对的机器人 link 几何。感知节点不读取 `BridgeObservation.object_pose` 或仿真双指接触来检测、跟踪或确认物体；oracle 仅用于隔离的离线评测。

感知处理分三层：

1. 根据同帧机器人 link 位姿与几何，在相机平面渲染机器人预测深度。只过滤观测深度与预测机器人表面相符的像素，保留机器人轮廓内更近或更远的深度；掩膜及容差必须可视化和定量验证。缺失对应位姿或输入无效时拒绝该帧，不使用旧 TF 静默补齐。
2. 在剩余点云里用盒体尺寸、几何残差和轨迹门限做候选关联，不再默认选最大簇。桌面上的物体可以使用支持平面先验；离桌后不能继续把盒体 z 锚定到桌面。模型不匹配、错误身份和目标丢失分别输出可诊断原因。
3. 建立随 session/generation 清空的时序跟踪。`MEASURED` 需要本帧物体像素支撑；`PREDICTED` 只能在曾有可靠测量、物体运动模型成立且年龄/不确定性未超限时给出有界 pose；`OCCLUDED` 表示没有可执行 pose；`REJECTED` 表示输入或几何证据冲突。预测年龄与不确定性随无测量时间增长。完全遮挡时不能宣称单相机确认了持物或未滑落。

扩展 `VisionObjectPose` 的状态、最近实测时间/序号、预测年龄和不确定性元数据，保留 bridge session、generation、当前样本序号与拒绝原因。旧 `accepted` 字段只对合格的 `MEASURED` 为 true；旧消费者遇到 `PREDICTED/OCCLUDED/REJECTED` 继续 fail closed。新任务适配层按显式状态处理，不能用预测 pose 冒充实测 pose，也不能把预测残差写成测量残差。

任务层只做必要的证据门适配：继续用新鲜关节/TCP/夹爪状态和 `EpisodeController` 的 reset、generation、sequence 生命周期；允许有时限的预测支持运动，超时或冲突必须停下。当前依赖物体高度、相对 TCP 距离和落点的 FSM 判据要区分测量与预测；预测不能单独触发“已抬升”“未滑落”或 `DONE`。释放并移开机械臂后，必须由新的 `MEASURED` 位姿验证落点；未能重见报告未验证或失败。vision 模式的在线成功判据不得借用仿真物体真值或接触位。oracle 模式保留为独立基线。

## Alternatives

Stage 4 最初手写了 OBJ 解析与 CPU 三角形栅格化，能在无显示服务的环境运行，但重复实现了成熟的网格加载和渲染能力。经安装与实测，改用 `geometric_shapes`/Assimp 加载可见网格、MoveIt 2 `moveit_mesh_filter` 输出预测深度；保留项目特有的同帧 TF、前景优先的深度比较和诊断。MoveIt 在 Humble 有库但没有可直接满足本项目时间戳契约的 ROS 2 self-filter 节点，因此仍需适配器。代价是依赖 OpenGL/X11；无头部署需虚拟显示或更换渲染后端；当前适配器明确拒绝同进程的相机尺寸或内参变化，因为固定几何测试发现重建过滤器后投影错位。`robot_body_filter` 主要基于 URDF collision 几何和点云 containment/ray 测试，不能直接替代当前的可见网格深度对比。

最初还把“观测深度比预测机器人表面更远”的像素比例作为整帧 `ROBOT_MODEL_MISMATCH` 拒绝门。第一次追问后移除了参数、计数和拒绝码，并错误地用机器人后方的正常场景内容解释冲突。后续追问纠正了遮挡关系：预测机器人若确实占据同一射线，后方物体应被遮住，bin/多 box 本身不使更远观测合理。2026-10-01 恢复 `comparison_pixels`、`mismatch_pixels`，仅用于诊断投影不一致；边缘栅格化和噪声可能产生少量冲突，不能由计数直接判定根因。原 50 像素、25% 拒绝阈值保持关闭，须先验证正常分布及 TF/标定偏差注入的区分能力。

只在 executor 锁定首帧视觉位姿、忽略后续拒绝，可以尽快让固定场景沿既有轨迹运动，但遮挡期间和最终落点仍缺独立证据，且把规划先验扩展成物理成功依据。用户决定优先建设可迁移的机器人感知与时序跟踪能力。

只加机器人掩膜、不加目标关联与时序状态，可以减少混簇，但在局部/完全遮挡、掉落、释放后重现时仍无法区分目标与机器人，也无法表达没有测量的时间。把预测一律发布为 `accepted=true` 会掩盖这一缺口。

新增相机或改变观察位姿可减少不可观测区，但当前先用单相机验证几何掩膜与跟踪边界；完全遮挡仍需显式超时或主动重新观察，不能假设算法能恢复不可见物体。

## Consequences

这一决策改变了 Stage 3 的“逐帧估计拒绝即终止”入口语义和视觉成功证据，不替换 ADR 003 的生命周期协议或 ADR 004 的控制器所有权。代价是模型几何对齐、掩膜渲染、跟踪状态、消息扩展、任务证据门与重放工具的维护成本。`mujoco_bridge` 不新增视觉算法或第二套 TF 发布者。

当前 Stage 3 的 `VISION_REJECTED` smoke test 仍是历史实测，不能再作为视觉抓放完成的验收。Stage 4~6 的目标与实测分开记录；Week 4.5 只接收完成验证后的证据状态契约。

## Verification

Stage 4 已通过固定几何测试、同帧运行时 RGB-D 掩膜叠加和缺 TF 注入。手写版本的 13 帧及 `5.84..16.31 ms` 是替换前基线；MoveIt 版本的 49 帧中 8110 个盒体像素无误掩，动态帧掩膜耗时约 `7.37..11.56 ms`，仍有盒体范围外前景点。独立 oracle 评测曾对照 `0.012 m` 与 `0.020 m` 容差，较大容差出现真实盒体像素误删，因此保留前者；vision episode 仍因局部可见目标置信度过低而停止。实际代码、评测计数和限制见 [architecture.md](../architecture.md#14-stage-4-实测与后续目标契约)。Stage 5 待用无 ROS 序列测试覆盖测量、预测、完整遮挡、错误关联、掉落、重见和跨 generation 重置，断言没有无像素支撑的 `MEASURED`。Stage 6 待运行相同 seed 的 oracle/vision 对照，完成固定场景连续抓放及 held-out 位姿、遮挡、掉落、丢帧与错误目标注入；成功必须有最终重新实测的落点。保留可重放的成功和失败数据，报告按 phase 的状态时长、误差、假成功次数和 p50/p95 延迟。具体阶段出口见 [week4.md](../../Job_guides/my_study/week4.md#24-stage-4同帧机器人几何掩膜)。
