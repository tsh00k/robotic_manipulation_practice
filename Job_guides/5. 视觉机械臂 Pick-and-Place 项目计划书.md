# 视觉机械臂 Pick-and-Place 项目计划书

> 项目定位：参考 Russ Tedrake 的 *Robotic Manipulation* Chap 3--6、8，用 **C++ + ROS2 + MuJoCo** 实现一个从 RGB-D 感知、抓取生成、运动规划到闭环控制的单臂 pick-and-place 系统。项目首先服务于机器人操作基础学习，其次形成可复现、可量化、能被面试深挖的公开作品。

课程入口：[Robotic Manipulation: Perception, Planning, and Control](https://manipulation.csail.mit.edu/index.html)

## 1. 项目要回答的问题

项目不是简单复刻 Drake notebook，也不是把几个现成包接起来录一段成功视频。最终应能回答：

1. 深度图如何变成世界坐标系中的物体或场景几何？感知误差如何影响抓取？
2. 一个几何上合理的抓取，是否对当前机器人可达、可规划、可执行？
3. 如何从抓取位姿得到连续、无碰撞、满足关节限制的轨迹？
4. 规划轨迹和真实执行之间由什么控制器连接？接触发生后为什么不能只依赖刚性位置跟踪？
5. 系统失败时，能否判断问题属于感知、抓取、规划、控制还是任务逻辑？

一句话项目描述：

> 在 MuJoCo 中构建带 RGB-D 相机的 Franka Panda 工作站，通过 ROS2 C++ 节点完成点云位姿估计、机器人感知约束的抓取选择、MoveIt 2 无碰撞规划与闭环轨迹/阻抗控制，并在随机物体位姿、遮挡和观测噪声下量化成功率与失败模式。

## 2. 范围控制

### 2.1 必做 MVP

- 单台固定基座 7 自由度机械臂，优先 Franka Panda 与平行夹爪。
- 单个已知刚体，桌面场景；先完成固定位置，再随机化位置和偏航角。
- 一个固定 RGB-D 相机；感知主线采用几何方法，不要求训练神经网络。
- 先以 MuJoCo ground-truth 物体位姿跑通全链路，再替换为视觉估计。
- 抓取以已知物体模板或点云几何生成候选，并经过碰撞与 IK 可达性筛选。
- MoveIt 2 + OMPL 负责全局无碰撞规划；接近和撤离段使用笛卡尔直线或约束轨迹。
- 先实现关节轨迹跟踪，再实现一个 Chap 8 对应的控制增量：computed torque 或 Cartesian impedance 二选一。
- 有状态机、失败恢复、日志、批量评测和可复现入口。

### 2.2 暂不进入 MVP

- 多类别开放世界识别、透明/柔性物体、灵巧手、双臂和移动操作。
- 同时实现 ICP、FoundationPose、端到端抓取网络、VLA 等全部路线。
- 自己从零实现完整的 RRT、碰撞检测器或深度学习训练框架。
- 为追求画面效果引入第二个仿真平台。
- 在单物体 pick-and-place 尚未稳定前做 bin clearing 或真机部署。

### 2.3 分层交付

| 层级 | 系统能力 | 交付价值 |
| --- | --- | --- |
| L0：基础闭环 | ground-truth pose + 固定 grasp + 关键帧/IK + 关节控制 | 验证 MuJoCo、ROS2、C++ 和机器人模型接口 |
| L1：项目 MVP | RGB-D 几何感知 + grasp 筛选 + 无碰撞规划 + FSM + 批量评测 | 可作为完整求职项目发布 |
| L2：深挖扩展 | 从每章扩展点中只选 1--2 个，形成对照实验 | 展示研究能力或对齐具体 JD |

只有上一层有自动化验收后再进入下一层。

## 3. 技术栈与系统边界

### 3.1 建议版本与依赖

| 层 | 首选 | 用途 |
| --- | --- | --- |
| 系统 | Ubuntu 24.04 + ROS2 Jazzy | 与当前长期支持的 ROS2 工具链对齐 |
| 语言 | C++17、CMake、ament/colcon | 所有核心节点、仿真桥、算法与测试 |
| 仿真 | MuJoCo C API/C++ wrapper、MuJoCo Menagerie 模型 | 动力学、接触、相机和 ground truth |
| 数学 | Eigen | 位姿、Jacobian、SVD、控制律 |
| 图像/点云 | OpenCV + PCL | RGB-D、点云滤波、分割、配准与可视化 |
| 运动规划 | MoveIt 2 + OMPL | RobotState、IK、PlanningScene、碰撞检查、RRTConnect |
| 控制接口 | `control_msgs`、`trajectory_msgs`，后续可接 `ros2_control` | 保持仿真和未来真机的命令边界一致 |
| 可视化 | RViz2 + MuJoCo viewer + rosbag2 | 坐标系、点云、候选抓取、轨迹和回放 |
| 测试 | gtest、launch_testing、批量 episode runner | 数学单测、节点集成测试和任务评测 |

机器学习扩展可以使用 Python/PyTorch，但必须封装成独立 ROS2 节点，并保持消息接口不变。核心项目仍应能在不安装模型权重的情况下运行几何基线。

### 3.2 机器人模型的一致性

MuJoCo 使用 MJCF，MoveIt 2 通常使用 URDF/SRDF。这会产生两个模型源，必须显式控制差异：

- 记录关节名、关节顺序、零位、轴方向、限位和末端 frame 的映射。
- 对至少 5 组固定关节构型比较 MuJoCo 与 MoveIt 2 的末端 FK，位置与姿态误差超过阈值就禁止继续集成。
- 碰撞几何允许简化，但必须记录与视觉几何、动力学几何的区别。
- 相机外参只由 TF 发布一份；禁止在感知节点中手写另一套外参。

这项模型一致性测试本身就是很好的工程展示点。

## 4. 总体架构

```text
MuJoCo world
  -> joint state / RGB-D / contact / ground truth
  -> ROS2 simulation bridge
       -> TF + JointState + Image + CameraInfo + Wrench
       -> perception node: RGB-D -> object pose / scene cloud
       -> grasp node: pose/cloud -> ranked grasp candidates
       -> planning node: candidate -> IK + collision-free trajectory
       -> task executor: observe -> plan -> execute -> verify -> recover
       -> controller: trajectory / pose -> joint command or torque
  -> simulation bridge -> MuJoCo actuator
  -> new observation
```

关键原则：感知、抓取、规划和控制之间通过明确的 ROS2 数据契约连接，不通过读取彼此内部变量耦合。ground truth 也必须走独立的 oracle 接口，不能偷偷混进正式感知输出。

### 4.1 ROS2 节点与接口

| 节点/包 | 主要职责 | 核心输入 | 核心输出 |
| --- | --- | --- | --- |
| `mujoco_bridge` | 固定步长仿真、传感器发布、执行命令、仿真复位 | joint trajectory / torque / gripper command | `/clock`、`JointState`、RGB-D、`CameraInfo`、contact、ground truth |
| `scene_perception` | 点云生成、ROI/桌面去除、目标分割、位姿估计 | RGB-D、TF | `vision_msgs/Detection3DArray`、scene cloud、置信度/残差 |
| `grasp_planner` | 生成、评分和筛选抓取候选 | object pose 或 segmented cloud、PlanningScene | `GraspCandidateArray` 或计算抓取 service |
| `motion_planner` | IK、规划场景、全局规划、接近/撤离和时间参数化 | grasp candidate、joint state、scene geometry | `JointTrajectory`、规划状态与失败码 |
| `arm_controller` | 轨迹跟踪或力矩/阻抗控制 | desired trajectory/pose、joint state、contact | actuator command、tracking diagnostics |
| `task_executor` | FSM/行为树、超时、验证与恢复 | 各模块状态、任务请求 | grasp/plan/execute 请求、任务结果 |
| `episode_runner` | 随机化、批量实验、指标汇总 | experiment config | CSV/JSON、rosbag、失败 episode 列表 |

优先复用标准消息：`sensor_msgs`、`geometry_msgs`、`vision_msgs`、`trajectory_msgs`、`control_msgs`。只有“带 score、抓取宽度、approach direction 的候选列表”确实无法清楚表达时，才新增 `manipulation_interfaces`。

## 5. Chap 3 模块：基础 Pick-and-Place 与运动学

课程对应：[Chapter 3: Basic Pick and Place](https://manipulation.csail.mit.edu/pick.html)

### 5.1 学习目标

- 将 frame、pose、transform、twist、Jacobian 和 joint state 落到 C++ 类型与 ROS2 TF 上。
- 区分 FK、full IK 和 differential IK 的输入输出与适用范围。
- 用 grasp/pregrasp、关键帧和夹爪开合时序构造第一条完整任务轨迹。

### 5.2 实现任务

1. 建立 Panda + gripper + table + cube 的 MuJoCo 场景。
2. 完成 `mujoco_bridge`：固定仿真步长、`/clock`、`JointState`、TF、位置/力矩命令、reset service。
3. 使用 ground-truth object pose 构造 `pregrasp -> grasp -> lift -> preplace -> place -> retract`。
4. 用 MoveIt `RobotState` 或独立数学模块计算 FK/Jacobian；用有限差分检查 Jacobian。
5. 实现 damped least-squares differential IK；记录最小奇异值、关节限位裕量与 tracking error。
6. 完成固定场景下的自动 pick-and-place，不依赖手工拖动或临时命令。

### 5.3 验收

- `T_ab * T_bc = T_ac`、inverse、四元数归一化和 frame 方向有单元测试。
- MuJoCo 与 MoveIt 2 的 FK 一致性通过固定样例测试。
- Jacobian 的解析值与有限差分结果在设定容差内一致。
- 固定物体位姿下连续成功 20 次，且无非预期碰撞。
- 日志能显示每个阶段、目标 frame、末端误差、最小奇异值和失败原因。

### 5.4 扩展点

- **约束 differential IK**：加入速度/位置限制、joint centering 和奇异区减速；比较“伪逆后裁剪”与“约束内求解”的路径偏差。
- **MoveIt Servo**：以成熟的在线伺服接口替换自写 diff-IK，比较接口、约束与实时性。
- **手眼标定练习**：人为扰动相机外参，用 AX=XB 或标定板流程恢复，连接 Chap 3 坐标系与 Chap 4 感知误差。

主线只实现第一个扩展；其余保留为面试讨论或后续 issue。

## 6. Chap 4 模块：RGB-D 与几何位姿估计

课程对应：[Chapter 4: Geometric Pose Estimation](https://manipulation.csail.mit.edu/pose.html)

### 6.1 学习目标

- 理解 depth、camera intrinsics/extrinsics、point cloud 和 world frame 的关系。
- 实现已知对应的 SVD 刚体配准，理解 ICP 的非凸性、初始化依赖、局部视图和离群点。
- 输出不仅包含 pose，还包含 residual、inlier ratio 和是否可信。

### 6.2 实现任务

1. 从 MuJoCo RGB-D 相机发布标准 ROS2 图像与 `CameraInfo`，用 TF 将点云变换到 `world`。
2. 对桌面 ROI 做 passthrough/voxel filtering、RANSAC 平面去除与目标聚类。
3. 为已知 cube 或非对称刚体准备 CAD/model cloud。
4. 自己实现一次“已知对应 + SVD”作为数学单测，再使用 PCL 的 global registration/ICP 完成工程版本。
5. 在不同初始化、遮挡、深度噪声和离群比例下记录 translation/rotation error、inlier ratio 和运行时间。
6. 将正式感知输出与 oracle pose 并排记录，但下游每次只能选择其中一个输入源。

### 6.3 验收

- depth -> point cloud -> world 的坐标变换可由 RViz2 与已知几何共同验证。
- 在 held-out 场景中报告位置误差、姿态误差、失败率与 p50/p95 延迟。
- 至少展示一个 ICP 因错误初值或对称性失败的反例，而不是只展示成功帧。
- 感知节点能拒绝低置信估计，任务层会重新观察而不是继续盲抓。

### 6.4 扩展点

- **鲁棒几何基线**：FPFH + RANSAC/TEASER++ 提供全局初值，再用 point-to-plane ICP 精修。
- **现代 6D pose**：在 CAD 已知且有 RGB-D 的条件下接入 FoundationPose 或 MegaPose；保持 `Detection3DArray` 接口不变，与几何基线比较精度、延迟和失败类型。
- **开放词汇分割**：使用 Grounding DINO + SAM 2 生成 mask，再做深度反投影和位姿估计。该路线适合展示感知前端，但不应替代几何与坐标系验证。
- **多视角/主动感知**：融合两个相机或移动到新视角，比较遮挡下的 pose 与 grasp 成功率。

求职版建议只选择“鲁棒几何基线”或“FoundationPose 对比”之一。

## 7. Chap 5 模块：抓取选择与任务层闭环

课程对应：[Chapter 5: Bin Picking](https://manipulation.csail.mit.edu/clutter.html)

### 7.1 学习目标

- 从 friction cone、antipodal grasp 和 contact wrench 的概念出发，理解抓取评分只是成功率代理。
- 将局部抓取几何、机器人 IK 可达性、路径可达性和碰撞风险分层处理。
- 用任务状态机连接低频决策与高频控制，并为失败设计恢复路径。

### 7.2 实现任务

1. MVP 使用已知物体坐标系中的 2--4 个模板 grasp；随后根据点云法向生成平行夹爪候选。
2. 为每个候选计算：antipodal/法向得分、重力方向余量、夹爪宽度、点云覆盖、预抓取碰撞和 IK 可行性。
3. 记录每次筛选的拒绝原因，禁止只返回“没有抓取”。
4. 实现显式 FSM：`OBSERVE -> SELECT_GRASP -> PLAN -> APPROACH -> CLOSE -> LIFT -> PLACE -> VERIFY -> RECOVER/DONE`。
5. 通过物体高度、夹爪宽度/接触和最终放置区域共同判断成功；不能只以轨迹执行结束作为成功。
6. 恢复策略至少包含：重新观察、换下一个 grasp、回安全位和有限次数重试。

### 7.3 验收

- 可视化候选抓取 frame、score、pregrasp 和碰撞/IK 筛选结果。
- 对 grasp 失败给出 `NO_GEOMETRIC_CANDIDATE`、`IK_INFEASIBLE`、`PLAN_FAILED`、`SLIP` 等分层错误码。
- 在随机物体位姿下完成批量任务；报告每层筛选通过率和最终成功率。
- 至少展示一次“几何评分最高但不可达”和一次“可达但路径不可行”的例子。

### 7.4 扩展点

- **学习式 6-DoF grasp**：Contact-GraspNet、GraspNet/AnyGrasp 或 VGN 任选一个，与几何候选生成器共享下游 IK/碰撞筛选；使用前核对模型和数据许可。
- **机器人感知约束的 reranking**：把可达性、路径长度、关节限位余量和感知不确定性加入候选排序，而不是只看局部点云质量。
- **BehaviorTree.CPP**：MVP 的 FSM 稳定后再迁移，展示 retry、fallback、timeout 和 recovery 的组合能力。
- **杂乱清空**：从单物体升级到 3--5 个物体；新增 double-pick、无可抓候选和推/重排策略。

优先推荐“机器人感知约束的 reranking”，它最能把 Chap 4--6 串成一个有技术含量的实验。

## 8. Chap 6 模块：IK、无碰撞规划与时间参数化

课程对应：[Chapter 6: Motion Planning](https://manipulation.csail.mit.edu/trajectories.html)

### 8.1 学习目标

- 区分单点 IK、differential IK、几何路径、带时间轨迹和控制参考。
- 理解 configuration space、非凸碰撞约束、局部优化与采样规划的取舍。
- 将 grasp feasibility 升级为完整的 robot-aware feasibility。

### 8.2 实现任务

1. 使用 MoveIt 2 `PlanningScene` 同步桌面、物体、相机支架和夹爪 attached object。
2. 对 grasp/pregrasp 做 IK 与碰撞检查；保留 joint-limit margin 较好的解。
3. 自由空间段使用 OMPL `RRTConnect`；接近、抬起、放下和撤离优先使用笛卡尔直线段。
4. 规划后做 shortcut/smoothing 与时间参数化；验证位置、速度和加速度限制。
5. 抓取后及时更新 attached collision object，再规划 place；不能继续把物体当成桌面上的静态障碍物。
6. 为规划设置时间上限、重试次数和结构化失败码，并保存失败场景用于回归测试。

### 8.3 验收

- 轨迹发布前和执行后都进行碰撞/限位检查。
- 报告规划成功率、p50/p95 规划时间、路径长度和重试次数。
- 同一候选能区分 IK 失败、全局路径失败、笛卡尔接近失败与执行失败。
- 在至少两种障碍布局中展示 planner 绕行，而不是只有空桌面直线运动。

### 8.4 扩展点

- **Pilz/工业轨迹**：为 approach/place 使用 PTP/LIN/CIRC 语义，比较其可预测性与通用 OMPL 规划。
- **TrajOpt/Tesseract**：将 RRTConnect 的路径作为优化初值，比较平滑度和 clearance。
- **cuRobo**：在 NVIDIA GPU 条件允许时，作为高吞吐 IK/规划基准与 MoveIt 2/OMPL 比较；不作为项目安装前置条件。
- **GCS/IRIS**：作为研究型支线复现二维或低维示例，解释同伦路径选择；不要在首版中强行移植到完整 Panda C-space。
- **在线重规划**：物体或障碍变化时取消当前 action、更新 PlanningScene 并重新规划。

求职版首选“RRTConnect + 笛卡尔段 + 时间参数化”，再增加一个规划对照，不同时集成三种 planner。

## 9. Chap 8 模块：轨迹跟踪、力矩与柔顺控制

课程对应：[Chapter 8: Manipulator Control](https://manipulation.csail.mit.edu/force.html)

### 9.1 学习目标

- 区分规划参考 `q_d(t)`、虚拟期望加速度、关节力矩和实际接触力。
- 理解 joint PD、重力补偿、computed torque、Cartesian impedance 与 hybrid force/position control 的接口差异。
- 认识仿真模型误差、饱和、接触瞬态和控制频率对结果的影响。

### 9.2 实现任务

1. 基线使用 MuJoCo position actuator 或关节 PD 跟踪 `JointTrajectory`，先建立稳定的任务闭环。
2. 记录 joint tracking RMSE、末端误差、最大 torque、接触 impulse 和控制循环 jitter。
3. 实现 computed-torque 或 Cartesian impedance 之一；控制器必须包含 torque limit、速度保护和异常停止。
4. 对物体质量、摩擦、控制频率和观测延迟做小范围扰动，比较基线与控制增量。
5. 在抓取闭合、放置接触或轻微位姿误差下验证柔顺性，避免把碰撞力峰值隐藏在成功视频中。

### 9.3 验收

- 参考、测量和输出 torque 在 rosbag 中可回放并对齐时间戳。
- 固定轨迹下报告 joint/Cartesian tracking error 和 torque/contact force 峰值。
- 控制器在超限、NaN、通信超时或规划中止时进入明确的安全状态。
- 对至少一种模型失配进行对照，说明“仿真中精确逆动力学”为什么不能直接等价于真实硬件表现。

### 9.4 扩展点

- **Cartesian impedance**：对比刚性位置跟踪在位置估计偏差下的接触力峰值与成功率。
- **Hybrid force/position**：增加擦拭或受约束放置小任务，切向跟位置、法向跟力。
- **Peg-in-hole**：作为独立扩展示范 remote-center compliance、角度误差与 jam，不并入 pick-and-place MVP。
- **残差学习/模仿学习**：让策略只学习模型控制器上的 residual 或接触阶段微调，而不是端到端替代整个可解释控制链。

对本项目最合适的扩展是 Cartesian impedance，因为它直接连接视觉误差、接触安全和 Chap 8 的核心思想。

## 10. 系统集成与实验设计

### 10.1 必须保留的 oracle 对照

系统按相同接口运行两种模式：

- `oracle`：ground-truth pose + 模板 grasp，用来验证规划与控制上限。
- `vision`：RGB-D pose/grasp，用来评估真实感知闭环。

若 oracle 都失败，不应调感知；若 oracle 稳定而 vision 失败，再定位 pose、grasp 或不确定性处理。这一对照能显著提高调试效率，也让实验结论可信。

### 10.2 评测场景

| 维度 | 基线 | 泛化/扰动 |
| --- | --- | --- |
| 物体 | 单个已知非对称刚体 | 未见位置、偏航角、小范围尺寸/质量变化 |
| 感知 | 无噪声固定相机 | 深度噪声、缺失点、遮挡、外参微扰 |
| 规划 | 空桌面 | 一个或两个固定障碍、不同起始构型 |
| 控制 | 标称质量/摩擦/频率 | 质量、摩擦、动作延迟和控制频率变化 |

### 10.3 建议目标值

这些是工程门槛，不是预先承诺的结果；首次稳定基线后可以按测量修订。

- Oracle 模式：随机初始位姿 50 episodes，成功率不低于 90%。
- Vision 模式：held-out 50 episodes，成功率不低于 70%，并报告 95% 置信区间。
- 感知：位置误差中位数小于 15 mm、姿态误差中位数小于 10°，同时报告对称物体的等价姿态定义。
- 规划：成功规划的 p95 时间低于 2 s；所有已发布轨迹无模型内碰撞。
- 控制：关节 tracking RMSE 小于 0.03 rad；所有命令满足预设 torque/velocity limit。
- 复现：固定配置与随机种子，至少在 3 个种子上给出均值、标准差和失败分布。

### 10.4 主实验建议

只选一个清楚的问题做项目主实验：

> 将感知置信度、IK/关节限位余量和路径代价加入 grasp reranking，是否比只按局部几何评分选择抓取，在未见物体位姿与深度噪声下获得更高的端到端成功率？

对照组：

1. 几何 grasp score only。
2. 几何 score + IK/collision filtering。
3. 几何 score + IK/collision + perception/planning-aware reranking。

指标：候选通过率、规划成功率、抓取成功率、端到端成功率、平均重试次数、p95 任务时间和失败类型。这一实验天然连接 Chap 4、5、6，且不依赖训练大模型。

## 12. 与 AI 一起边学边练的工作方式

AI 的价值应是缩短样板代码、定位和复盘时间，而不是替代对关键算法的理解。

### 12.1 每个 issue 的固定循环

```text
写清输入/输出/坐标系/频率/成功条件
  -> 先写最小测试或可观测量
  -> 让 AI 生成包骨架、CMake、消息和测试样板
  -> 自己实现核心数学与状态转换
  -> 让 AI 做代码审查、边界条件和故障注入
  -> 跑实验并记录失败
  -> 写一条 ADR 或 weekly_log
```

### 12.2 必须自己掌握的代码

- 位姿链与 frame 转换。
- FK/Jacobian 的含义、有限差分验证和奇异性判断。
- SVD registration/ICP 的目标函数和失败条件。
- grasp score 的每个项及其物理含义。
- 规划输入、约束、失败码和 attached object 更新。
- 控制律、单位、符号、饱和和安全边界。

AI 可以生成 ROS2 boilerplate、launch/config、参数解析、日志、测试 fixture、绘图脚本和文档初稿，但关键公式不能以“代码能跑”为验收。

### 12.3 推荐提问模板

```text
当前模块：Chap X / <module>
输入：消息类型、frame、频率、单位
输出：消息类型、frame、频率、单位
已有测试：...
实际现象：...
期望现象：...
请先判断问题属于数学、ROS2 接口、时序、MuJoCo 模型还是数值稳定性；
给出最小诊断步骤，不要直接重写整个模块。
```
